Portifo · Design System

Screens

Every screen in the app, rendered at true iPhone 16 scale — 393 × 852pt, 1pt = 1px. Every measurement on this page is the measurement to build to: nothing is indicative, nothing is cropped to fit. Each screen carries a spec block covering only what is specific to it: the order of its sections, its data, and the states that aren't visible in a single still. The rules live in guidelines.html — colour, type, layout constants, the page header's states, the tab bar — and are deliberately not repeated here.

The Frame

iPhone 16 is the reference device. The app owns the full 393 × 852pt viewport; the status bar and home indicator sit inside it, so both safe-area insets come out of the app's own layout. Side hardware on these mockups is decorative — it never overlaps the viewport. Only device geometry is listed here. The layout constants it holds — --gutter, --sec-gap, the section-head divider, the page header's states and the tab-bar spec — are defined once in guidelines.html; this page shows how they compose.

Holding Detail · build notes
HeaderState 3a — pushed screen at rest, title carrying the ticker and the back button labelled Portfolio. Pushed, so no tab bar: the 34pt bottom inset belongs to the page.
ContinuityHero repeats the exact shape of the row that opened it — price / share, cost basis, stacked Today/Total — so the transition reads as a zoom, not a new screen. Company name is the subtitle under the title.
By AccountBreaks the position down per account and always sums to the Shares stat. Read-only, so no chevrons.
ActionsBuy/Sell sit at the end of the scroll, not pinned, so the screen scrolls to reach them.
FoldMeasured: the page is 950pt against an 852pt frame — 98pt of overflow, so at rest the fold falls across the Buy button. That cut is real geometry, not a crop: nothing here is pinned, and scrolling brings the stack fully into view with its 34pt bottom gutter intact (state 3b in guidelines.html).
StatesA fully-closed position drops the action stack for a single "Realized P&L" stat and demotes the chart to the holding period.

Transactions · build notes
HeaderState 1, Transactions row of the header table — no chevron, + adds a transaction.
GroupingOne .divider per calendar month, newest first, with the count as .dm. Months are the only grouping — no search, no type filter.
RowsA row reads what moved · what happened · how much: .sym is the ticker for Buy/Sell and the currency for Deposit/Withdraw, .name is type · account, .val is the total and .meta the date. Share maths stays on the detail screen — at these name lengths it collided with the account.
GlyphsDirection only — arrow into the line for money in (Buy, Deposit), out of it for money out (Sell, Withdraw). Cash movements take the tinted well, trades the neutral one, matching the Cash row on Portfolio. Never gain/loss colour: a Buy is not a loss.
AmountsShown in the transaction's own currency (€1,200.00 stays euros), not the display currency — this is a ledger, so it must match what the user entered.
StatesEmpty portfolio shows the shared empty state with the same + CTA. Rows push a read-only Transaction Detail; editing is an explicit action there, never a swipe on this list.
Not drawnThe app carries a Symbol / Type / Account filter row above the list that this mock does not show, and a "no matches" empty state for it. The row above is otherwise built as drawn. Either the filters get designed into this card or they get dropped — open decision, and until it is made the shipped screen has one element with no spec.

Accounts · build notes
HeaderState 1, Accounts row of the header table — no chevron, + adds an account.
GroupingInvestment first, then Cash — the order the two types were created in onboarding, and the order they matter in. Never mixed into one list: the types behave differently.
RowsAccount name in the display face (it is a name, not a figure), type as the subtitle, total value as .val, and what the total is made of as .meta — holdings for Investment, currency count for Cash.
NumbersThe three totals sum to the $148,296.05 hero on Portfolio — the same money, sliced by account instead of by holding. An Investment Account's total also carries any cash its Deposits left in it; both accounts here are fully deployed.
StatesEmpty until the portfolio has a transaction or a cash balance — the two onboarding accounts exist but the tab still shows the shared empty state. Rows push Account Detail, which differs by type: an Investment Account has Holdings + Cash lists, a Cash Account only per-currency balances.

Add Transaction · build notes
HeaderState 3a — pushed, not a sheet, so the back button carries the parent's name and doubles as cancel. Reached from any +; the label changes to Edit Transaction when opened from a Transaction Detail.
TypeThe segmented control is the first field because it decides the rest: Buy/Sell ask Symbol + Shares + Price / Share, Deposit/Withdraw replace those three with Amount. Account, Date and Currency are always asked.
AccountPicker over existing Investment Accounts, and typing a new name creates one — a transaction can never belong to a Cash Account. Pre-filled from context: the tab's account, or the first Investment Account created.
TotalComputed, never entered — a rule divider heading the figure, not a field, so it cannot read as editable. It restates the maths from the two inputs above it and is the only figure on the screen.
StatesSave is btn-disabled until the type's required fields are filled. Currency defaults to the account's currency; date defaults to today. No delete here — that lives on Transaction Detail.

Settings · build notes
HeaderState 1, Settings row of the header table — the one tab with no trailing action. New portfolios are created from a row, not from the bar.
OrderAccount → Portfolio → Appearance → Log Out: identity, then what you are looking at, then how it looks, then the way out. Four .divider sections, no nesting.
RowsThe email row is the only one with no chevron — nothing to open, since Google owns the identity. Every Portfolio row pushes: the active one to its members and accounts, New Portfolio into onboarding for the portfolio it creates.
AppearanceA segmented control, not a pushed screen — three options, instant effect, so the choice and its result are on the same screen. System is the default and follows the OS.
Log Outbtn-secondary, not destructive red: signing out destroys nothing, the data is server-side. Confirms first, then returns to Login.

Portifo · Design System

Screens

Every screen in the app, rendered at true iPhone 16 scale — 393 × 852pt, 1pt = 1px. Every measurement on this page is the measurement to build to: nothing is indicative, nothing is cropped to fit. Each screen carries a spec block covering only what is specific to it: the order of its sections, its data, and the states that aren't visible in a single still. The rules live in guidelines.html — colour, type, layout constants, the page header's states, the tab bar — and are deliberately not repeated here.

The Frame

iPhone 16 is the reference device. The app owns the full 393 × 852pt viewport; the status bar and home indicator sit inside it, so both safe-area insets come out of the app's own layout. Side hardware on these mockups is decorative — it never overlaps the viewport. Only device geometry is listed here. The layout constants it holds — --gutter, --sec-gap, the section-head divider, the page header's states and the tab-bar spec — are defined once in guidelines.html; this page shows how they compose.

Holding Detail · build notes
Two pagesThis screen is the portfolio scope only. The account and lot scopes live on Account Holding, one push deeper. Both pages repeat the same block — .divider head, .stat-grid, return lines — so the push reads as a zoom.
HeroMarket value, not price — this is a portfolio tracker and it is the same figure the Holdings row shows, so the push still reads as a zoom. Price/share moves down to the Market block.
TodayToday's percentage is identical at every scope — it is a property of the security, not the holding. It belongs to the hero of whichever page you are on, and never appears on a row that already shows total return.
Account rowsThey push, so they carry a chevron (rule 09) — that is the whole affordance. Measured: the chevron leaves 179pt for the left column, so the meta line stays 160 sh · avg $27.79; adding a lot count wrapped it to two lines and pluralised badly at one lot. Value over total return on the right; the lots are one tap away, not crammed in.
No chartPortifo does not compete with a charting product. The Market block carries the live price and hands the chart to Yahoo Finance — finance.yahoo.com/quote/{symbol}. The provider is not a preference: market.service.ts already prices through yahoo-finance2, so every stored symbol is a Yahoo symbol, exchange suffixes (.TO, .L) included, and the link cannot resolve to the wrong instrument. TradingView needs an exchange prefix (NASDAQ-NVDA) the app does not store.
Market is a gridIt was a .field-card, and that was wrong twice over. Visually, two read-only blocks sat 20px apart in two vocabularies — label-left/value-right vs stacked, Inter 13px --fg-2 labels vs mono 10px uppercase --fg-3, values at 13.5/500 vs 15/600. Semantically, .field-card is the form idiom (a label and its answer, with .field-input and .field-value.empty prompts) — and Add Transaction has a Price / Share row in that exact treatment that you type into. Same label, same look, opposite affordance. Market is now a one-row .stat-grid, so the screen reads divider → grid, divider → grid and .field-card means editable everywhere in the app.
Leaving the appAn outward arrow, never a chevron — rule 09 reserves the chevron for a push onto the navigation stack, and this is not one. The whole cell is the anchor (a.stat-cell), a 59pt target against the old row's 44pt, and .stat-link gives the second line the display face and --signal so an action never reads as a figure. Opens in the system browser (or the Yahoo Finance app via its universal link); it must never replace the PWA's own window, or the back gesture strands the user outside the app.
Hero metaThe old 263 sh · $189.09 / share line is gone. Share count belongs to the position and lives in the grid; live price belongs to the security and lives in the Market block. The hero is market value and its two returns, nothing else.
RealizedClosed money, so it sits outside the grid on its own line rather than becoming a fifth cell that reads like part of the open position. Hidden entirely when nothing has been sold.
FoldMeasured: 928pt against an 852pt frame. The resting view ends on a complete Buy button (789–837pt); Sell starts at 846pt and shows a 6pt sliver, its label safely at 861.5–878.5pt, so nothing legible is bisected (rule 12 — verified by walking every text node, not by eyeballing the button box). The action stack's double --sec-gap is what buys that. Converting Market from a .field-card to a one-row .stat-grid took 28pt off (89pt → 61pt), which at a single gap pulled Sell up to 822–870 and put the fold through the middle of its label. The gap is local to this screen on purpose: the other four button screens measure 852pt exactly, so a system-wide change would push all three of them over. The stack also shifts with the account count — re-measure before changing anything above it. Nothing is pinned.
Single accountWhen only one account holds the position the Accounts section still renders — one row, one chevron. Never inline the deeper scope as a special case; that would be two layouts for one screen.

Account Holding · build notes
TitleThe account name, because the back button already says NVDA — together they read as the breadcrumb "NVDA → Fidelity Brokerage". The subtitle carries NVDA · NVIDIA Corp so the ticker is never more than a glance away.
No Market blockLive price and the chart link are properties of the security, so they live once on the parent page. This page carries no security-level content at all — it is about your shares, which is also why its hero meta line went.
Same blockHero, then the same four .stat-grid cells in the same order, then the realized line. Only the scope of the numbers changed, which is the whole point of the push.
Lot rowIt is the Accounts row, not a shape of its own — same .row anatomy, same measures, one section further down the same page. 60 @ $13.20/share takes the .row-name slot: a lot is a quantity of shares at a price, so that sentence is the lot's name and reads at the same weight as the account rows above. @ and /share say what the two numbers are to each other, where 60 sh · avg $13.20 made the reader supply the relation. The unit is /share and not the fuller per share for measure, not taste: the left column is 205pt wide on a 390pt screen once the right column has its money, and at the row's 14px mono 209.01 @ $221.27 per share measures 218pt — it wrapped, and a wrapped name line drops the meta line out of alignment with the return beside it. The /share form is 185pt and clears it. Measure any new lot line against that 205pt. The name line also replaced $792.00 (60 × $13.20) — the total-(count × unit) idiom belongs to a row whose right column is not already the total, and here it was: cost basis on the left and market value on the right made two totals per row and the reader had to work out which was which. Line 2 is 5y 5m · Feb 12, 2021 — age first, because age is what this section is sorted on and what the reader came for; the date follows so the exact purchase is still on the page. Right column is unchanged — market value over total return.
Lot orderOldest first. Age is the reason lots exist on this screen, so it drives the sort.
UnderwaterCarries no tint of its own. A lot bought above the current price already shows a --loss total return in the right column, which is where the app says gain and loss everywhere else; tinting the name line too said it twice and made a row's identity change colour with the market. The name line is a name — it takes --fg-1 whatever the numbers beside it are doing. (The earlier .under modifier is gone.)
No lot P&L for todayToday's return per lot is the position's return scaled by share count — the same percentage on every row. It distinguishes nothing between lots and is omitted.
Big returnsPercentages ≥ 1000% drop the decimal (+1332%) — the tenth of a percent is noise at that magnitude and the extra glyph breaks the column.
ActionsScoped: they open Add Transaction with both the account and the symbol prefilled, which is the reason to be on this page rather than the parent.
Lots are read-onlyNo chevron (rule 09). A lot is not a transaction once it has been partly sold, so pushing to the originating buy would be a half-truth.
FoldRe-measured after the lot row became a .row: a lot grew 56pt → 63pt (the row's 13pt padding and 14px name line against the old 10pt and 12.5px), so the content runs to 859pt including the 34pt home-indicator pad. A three-lot position still needs no scroll — Sell ends at 825pt inside the 852pt frame, nothing legible bisected (rule 12). Budget ~63pt per additional lot: the fourth pushes Sell to ~888 and the screen starts scrolling, which is correct — it is a list.
Cost basisThe app is average cost (ACB) throughout — no screen mixes methods. Under ACB a sale comes out of an undifferentiated pool, so a lot is not drawn down FIFO. The ACB-native model is a pro-rata drawdown: selling 40 of 160 shares shrinks every open lot by 25%. That is exact, not an approximation — removing the same fraction from every lot removes exactly that fraction of total basis, so the surviving lot costs still sum to the Cost basis stat above them. Each lot keeps its own purchase price and date; only its share count shrinks, which is why fractional share counts (41.25) are normal here and not a rounding artifact.
Lot datesFormatted en-US like every other date in the app, but with a 2-digit day where the rest of the app uses numeric — these dates form a column, and rule 10 wants a column of figures to line up. They sit in .row-sub, which is already mono, so they need nothing of their own. The name line is the one that does: .lot-figs keeps the mono face while taking .row-name's 14px/600, because an account name is a proper noun and takes the display face while 60 @ $13.20/share is a figure. Same size, same weight, same baseline as the rows above — only the face differs, and it differs for the reason rule 10 gives.

Transactions · build notes
HeaderState 1, Transactions row of the header table — no chevron, + adds a transaction.
GroupingOne .divider per calendar month, newest first, with the count as .dm. Months are the only grouping — no search, no type filter.
RowsA row reads what moved · what happened · how much: .sym is the ticker for Buy/Sell and the currency for Deposit/Withdraw, .name is type · account, .val is the total and .meta the date. Share maths stays on the detail screen — at these name lengths it collided with the account.
GlyphsDirection only — arrow into the line for money in (Buy, Deposit), out of it for money out (Sell, Withdraw). Cash movements take the tinted well, trades the neutral one, matching the Cash row on Portfolio. Never gain/loss colour: a Buy is not a loss.
AmountsShown in the transaction's own currency (€1,200.00 stays euros), not the display currency — this is a ledger, so it must match what the user entered.
StatesEmpty portfolio shows the shared empty state with the same + CTA. Rows push a read-only Transaction Detail; editing is an explicit action there, never a swipe on this list.
Not drawnThe app carries a Symbol / Type / Account filter row above the list that this mock does not show, and a "no matches" empty state for it. The row above is otherwise built as drawn. Either the filters get designed into this card or they get dropped — open decision, and until it is made the shipped screen has one element with no spec.

Accounts · build notes
HeaderState 1, Accounts row of the header table — no chevron, + adds an account.
GroupingInvestment first, then Cash — the order the two types were created in onboarding, and the order they matter in. Never mixed into one list: the types behave differently.
RowsAccount name in the display face (it is a name, not a figure), type as the subtitle, total value as .val, and what the total is made of as .meta — holdings for Investment, currency count for Cash.
NumbersThe three totals sum to the $148,296.05 hero on Portfolio — the same money, sliced by account instead of by holding. An Investment Account's total also carries any cash its Deposits left in it; both accounts here are fully deployed.
StatesEmpty until the portfolio has a transaction or a cash balance — the two onboarding accounts exist but the tab still shows the shared empty state. Rows push Account Detail, which differs by type: an Investment Account has Holdings + Cash lists, a Cash Account only per-currency balances.

Add Transaction · build notes
HeaderState 3a — pushed, not a sheet, so the back button carries the parent's name and doubles as cancel. Reached from any +; the label changes to Edit Transaction when opened from a Transaction Detail.
TypeThe segmented control is the first field because it decides the rest: Buy/Sell ask Symbol + Shares + Price / Share, Deposit/Withdraw replace those three with Amount. Account, Date and Currency are always asked.
AccountPicker over existing Investment Accounts, and typing a new name creates one — a transaction can never belong to a Cash Account. Pre-filled from context: the tab's account, or the first Investment Account created.
UnansweredDrawn here fully filled. A field with no value yet shows its prompt — Select account, Select symbol — at --fg-3 via .field-value.empty, never the --fg-1 a real value gets (see Fields in guidelines). Date and Currency always carry a default, so they are never in this state.
TotalComputed, never entered — a rule divider heading the figure, not a field, so it cannot read as editable. It restates the maths from the two inputs above it and is the only figure on the screen.
StatesSave is btn-disabled until the type's required fields are filled. Currency defaults to the account's currency; date defaults to today. No delete here — that lives on Transaction Detail.

Settings · build notes
HeaderState 1, Settings row of the header table — the one tab with no trailing action. New portfolios are created from a row, not from the bar.
OrderAccount → Portfolio → Appearance → Log Out: identity, then what you are looking at, then how it looks, then the way out. Four .divider sections, no nesting.
RowsThe email row is the only one with no chevron — nothing to open, since Google owns the identity. Every Portfolio row pushes: the active one to its members and accounts, New Portfolio into onboarding for the portfolio it creates.
AppearanceA segmented control, not a pushed screen — three options, instant effect, so the choice and its result are on the same screen. System is the default and follows the OS.
Log Outbtn-secondary, not destructive red: signing out destroys nothing, the data is server-side. Confirms first, then returns to Login.

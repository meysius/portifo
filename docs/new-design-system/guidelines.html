Portifo · Design System

Guidelines

The rules behind the screens. Read this before writing or changing any UI. Every value here is a live token — the swatches and specimens below are painted by the same CSS the app uses, so this page cannot drift from foundations/. Screens that apply these rules live in screens.html.

01 — Color

Color schema

Never write a literal color in a component. Every color is one of the semantic tokens below, defined once in foundations/tokens.css and remapped per theme. The raw palette (--paper-*, --graphite-*, --cobalt*) exists only to feed these — components must not reference it.

Surfaces & structure

--bg
Page canvas. In light this is pure white and identical to --surface.
--surface
Cards, toolbars, tab bar. In light it equals --bg, so a card is separated by its hairline, not fill or elevation.
--surface-2
Subtle fills only: chips, segmented controls, glyph wells, ghost buttons, inline code.
--border
Every hairline: card edges, row separators, dividers, grid lines. Translucent — see rule 01.

Text

--fg-1
Primary: titles, figures, row values, symbols.
--fg-2
Secondary: body prose, row subtitles, field labels.
--fg-3
Tertiary: eyebrows, section labels, meta lines, units, chevrons.

Signal & semantics

--signal
The one accent. Primary buttons, back links, active tab marker, focus rings.
--signal-tint
Accent wells: header action buttons, badges, the Cash glyph.
--gain
Positive money only. Never for success/confirmation UI.
--loss
Negative money, and destructive actions only. Selling is not destructive.

Transaction type

The system’s one categorical palette, and the only place four hues are spent at once. It exists because the Transactions row has no glyph — the type chip is the only thing on that row saying what kind of movement it is, so it earns colour where a redundant mark would not. Used on .tx-tag and nowhere else.

--tx-buy
L*50. Nearest neighbour is --signal at ΔE 15.5 — the closest anything comes to the one accent.
--tx-sell
L*44. Darker than an ochre wants to be, because at L*53 it read as --loss for a deuteranope.
--tx-deposit
L*46. Pushed off green toward true teal so it cannot be read as --gain.
--tx-withdraw
L*31. The deliberate outlier — this value is what separates it from --tx-buy.

The lightness spread is load-bearing, not styling. Under dichromacy colour is roughly two-dimensional — one chromatic axis plus lightness — and these four cannot separate on hue alone. Drawn at a common L*46–55, the first version put --tx-buy against --tx-withdraw at ΔE 2.4 for a protanope, which is invisible. Spread across L*31–50 the tightest pair is ΔE 15.2 across normal, deuteranopic and protanopic vision in both themes, roughly double the ΔE 6.5 this document already calls too close. Flattening the values to tidy them up re-breaks the palette.

Do

Keep every collision against --gain, --loss, --signal and --fg-3 at ΔE ≥ 10, and ink on its own 12% tint at ≥ 4:1. Re-measure if any value moves — these were computed, not eyeballed (rule 11).

Don't

Spend these anywhere but the type chip, and never map Buy to --gain or Sell to --loss. A Buy is not a loss, and those two hues mean return everywhere else in the app.

Weight is coloured in exactly one place

--cat-1..4 and --cat-cash key a holding to its slice of the allocation bar on the Portfolio screen, and nothing else. This palette does not pass the test the transaction-type palette above passes: it is keyed by rank, so a hue changes meaning whenever prices move, and it recycles at the fifth holding, so a six-position portfolio paints two slices alike. It is legal in the bar anyway for one reason — the legend sits directly under it, naming every slice and printing its percentage. The hue is a pointer between two adjacent marks, not the encoding. Take the legend away and the bar becomes unreadable, which is why the two are one component and never shipped apart.

Everywhere the legend is not adjacent, weight carries no colour and no length. Three second encodings have been drawn into the holdings row and all three are gone: a 30pt .row-w figure leading it, a 6pt --signal bar on the separator, and a .w-tag chip beside the ticker. Each said a number the bar and legend 40pt above had already said, and the first two charged 50pt of every row's leading edge to say it. The Portfolio screen carries two charts and they answer different questions — the value curve is the total over the selected range, Today's movers is the current day broken down by holding — plus one partition bar with its key. One accent (--signal: header action, tab marker, --cat-1) and --gain/--loss reserved for return.

Do

Ship the bar and its legend together, and state each share exactly once — in the legend. The bar answers what no column of figures does: whether the portfolio is one position wearing a disguise.

Don't

Repeat the share on the row. A 2pt grey bar, a 6pt cobalt bar, a cumulative rail, a hue ramp, a tinted row plate and a .w-tag chip have each been built and each dropped. Don't spend --cat-* outside the bar, and never colour a weight mark --gain/--loss: the movers block already colours by direction, and those two separate at only ΔE 6.5 under deuteranopia.

Elevation

Nothing in this language casts a shadow. Every edge — card, tab bar, collapsed header — is a single 1px --border hairline, in both themes. That is what makes light and dark read identically, rather than light being a set of floating slabs and dark a set of flat panels. All three tokens below survive for documentation chrome only; dark mode resolved them to none long before this. Never hard-code a shadow and never re-attach one — if an element needs separating, it gets a hairline or it gets the header's blur material.

TokenApplied toDirection
--shadow-cardNo app component. Documentation chrome only — .card, .spec and this page's specimensAmbient. .chart-card, .stat-grid and .field-card are flat: one hairline, no lift
--shadow-barNothing — unused. The tab bar is separated by its 1px --border top hairline aloneCast up. Dropped so the bar sits flat against content like every other edge in the language
--shadow-navNothing — unused. The collapsed bar is separated by .ph-material.solid and its hairlineA shadow under a bar that already has a hairline doubles the edge. The material is the separator
02 — Typography

Typography

Three faces, three jobs, no overlap. The job decides the face — never the visual weight you happen to want. All three are self-hosted variable woff2 in foundations/fonts.css; there is no network font fetch.

Holding row

The Portfolio list only. Ticker over name starting at the gutter like every other list in the app, value over Total on the right, chevron. The share is not on this row — the allocation bar and its legend state it a section above, and every attempt to restate it here (a leading figure, a separator bar, a .w-tag chip) has been removed. The only chip in the .sym slot is .closed-tag, which says what the row is. .name clips rather than wraps, which is what keeps every row the same height — and that rule is scoped to .list-hold, the list, not to any weight mark.

Transaction row

The Transactions list only. Same .row skeleton as a holding, three differences, and each one pays for the last. The leading 30pt is a day stamp, not a glyph — the glyph could only say what the type chip says in words, and the row needed that space for something not already stated; the month is the section head, so the rail states only what varies inside the group. The type is a chip on the ticker’s line, not a word buried in the subtitle. The .meta slot carries the arithmetic, 12 sh @ $187.32, sitting directly under the total it multiplies to — the row shows its own working, which is what a trade confirmation does. Do

Let the account be the thing that clips. .tx-calc never wraps and never truncates — it is the widest thing in the right column, and the account absorbs the variation. Measured at 393pt the account gets 111–145pt; the Sell row is tightest because its P&L line is the widest figure.

Don't

Re-add a glyph beside the chip, label the Sell line Realized:, or sign the total. The first says the type twice, the second costs 50pt of the account to say what the only tinted figure in a ledger row could already only mean, and the third makes the sign mean cash-flow direction while nothing else does.

Filter row

Transactions only, directly under the page title. Chips size to their content — three flex:1 chips split 353pt into 113pt each and then spent a 10.5pt uppercase label on top of each value, so Wealthsimple TFSA arrived as Wealthsim… in a control whose whole job is to show what you filtered by. A chip states its dimension when unset and its value when set; the label was saying what the value already says. One line at 34pt, scrolling rather than truncating.

Today’s movers

Sits under the value chart on the Portfolio screen, and only there. The two are not redundant: the chart is the total over the selected range, this is the current day broken down by holding — which line moved the total, and by how much, which no range of the curve can say. One neutral baseline, gains right and losses left, sorted by size of contribution and scaled to the largest. The day’s total rides on the divider’s .dm — the one place in the system where a divider’s meta is tinted, because it is money.

Allocation

One component, two parts, never shipped apart: a 10pt partition bar cut into a slice per line — cash first, then holdings by value — and the legend under it naming every slice with its share. The bar answers the one question a sorted column of figures does not, which is whether the portfolio is a single position wearing a disguise; the legend is where the percentage is actually read, and it is what makes --cat-* legal here (see Weight is coloured in exactly one place above). Slices are separated by 2px of ground rather than hairline borders — a 1% slice is 3.6px wide at 393pt and a border would eat most of it — and floor at min-width:2px.

Do

Keep the legend order identical to the bar order, cash first. The reader matches slice to label by position first and hue second, which is what keeps the block readable once the palette recycles at the fifth holding.

Don't

Draw the bar without its legend, print the share a second time on the holdings row, or extend --cat-* past five values to stop the recycling. More hues will not separate; the labels are what disambiguate.

Cards

Three card types — .chart-card, .stat-grid, .field-card — must be visually indistinguishable at the edge: 8px radius, exactly one layer of --border, and no shadow. The hairline is the whole edge; a card sits on the plane, it does not float above it.

The edge is where they match; the inside is where they divide, and the division is by affordance, not by content. A .field-card is editable — every row of it is something the user answers. A .stat-grid is settled — measures the app computed, which the user reads. Picking between them by asking “is this a list of pairs?” is what put a read-only price into the form vocabulary on Holding Detail; ask “can the user change this?” instead.

Do

Draw internal rules full-bleed to the card's inner edge. If the card has side padding, cancel it with negative margins (see .ranges).

Don't

Give an element both background:var(--border) and border:1px solid var(--border). The border composites over the background and the edge renders at ~2× weight.

Do

Put read-only figures in a .stat-grid, even when there are only two of them and a pair of rows would have fit.

Don't

Stack a .field-card and a .stat-grid on one screen as two read-only blocks. Two label faces and two value weights, 20px apart, and neither one is wrong on its own — that is what makes it unfixable by tuning.

Fields

A .field is a label and its answer, so a field card only ever appears on a screen that asks the user something — a form, a picker, an editable detail. Nothing read-only lives here; it belongs in a .stat-grid. The answer is a figure — mono, --fg-1 — only once it exists. Until then the row holds a prompt, and a prompt is --fg-3: .field-value.empty on picker rows, the native placeholder on typed ones. Both states keep the same face and size, so answering a field changes its ink and nothing else — no reflow, no jump.

Do

Let the card be readable as a checklist. Scanning the ink alone must answer “what is still missing?”, which is also what the disabled Save button is waiting on.

Don't

Render a prompt at --fg-1. “Select account” then weighs exactly as much as USD and the form reads as complete while Save sits disabled with no visible reason.

Nested scopes

A screen that shows the same measures at more than one magnification splits into pages, never an accordion. Holding Detail is the portfolio scope; tapping an account pushes Account Holding, which is that account’s scope plus its lots. Every page repeats the same block in the same order — a .divider head, a .stat-grid for the cost side, then return lines — so the reader learns it once and the push reads as a zoom rather than a new screen. The app already has one way to go deeper; a second one on the same screen is a second thing to learn.

Do

Give each scope its own hero. The figure at the top of a page is that scope’s market value, so Today and Total always belong to the page you are standing on.

Don’t

Repeat a measure at a scope where it carries no information. Today’s percentage is a property of the security — identical at every scope — so a row that already shows total return does not also show it.

03.1 — Page header

Page header

One component, one behaviour, every screen: a 24px .ph-large title at rest that collapses into the 17px .ph-bar-title as it scrolls under the bar. Ionic drives the swap from collapse="condense" — never hand-write a scroll listener. Tab roots and pushed screens use the same title; a pushed screen only adds a back button, which lives in the bar and never scrolls. A bar title on a screen that has not scrolled is a bug — it is the collapsed state rendered at the wrong scroll position. Across the collapse the material fades in rather than popping, and the title cross-fades — it does not slide.

04 — Implementation rules

Instructions to myself

Every rule below exists because it was violated once and the render disagreed with the intent. Work through these before claiming a UI change is done.

01
Never paint --border twice. It is translucent, so an element with background:var(--border) and border:1px solid var(--border) renders its outer edge at ~2× weight. Use padding:1px and let the background show through instead.
02
An internal rule is never inset by its card's padding. Cancel side padding with negative margins so hairlines run edge to edge, matching .stat-grid.
03
One gap, one header style. Section spacing is --sec-gap via .sec/.sec-gutter; section heads are .divider. If you reach for a custom margin or a bold sans title, stop.
04
Watch specificity when scoping. .screen .divider (0,2,1) out-specifies .sec (0,1,0) and will silently kill its margin-top. Set only the properties you mean, never the shorthand.
05
Shadows are light-mode only. All --shadow-* tokens are none in dark, where surfaces already differ by value. Set them in both dark blocks — @media (prefers-color-scheme:dark) and :root[data-theme="dark"].
06
Reference tokens, never literals. var(--font-display) not 'Inter'; var(--gutter) not 20px. The display face has already changed once — the token made it a two-line diff instead of an 18-site edit.
07
This is Ionic, not Framework7. Name real components: IonHeader, IonToolbar, IonTitle, IonBackButton, IonTabBar. The collapsing title needs <IonContent fullscreen> plus a second <IonHeader collapse="condense"> inside it — miss either and it silently no-ops. Pushed screens use the same pair, with the ticker as the large title; that is what makes the bar title absent at rest and faded in on scroll, without a line of scroll code.
08
Do not double-apply safe areas. IonHeader and IonTabBar already inset themselves. Only pushed screens with no tab bar add the 34pt bottom gutter manually.
09
Chevron honesty. A row shows a chevron if and only if tapping it pushes a screen. Read-only rows (By Account) carry none.
10
Every comparable number is mono and tabular. Money, percentages, share counts, dates, tickers. A figure in the body face is a bug. One exception: a ticker used as a page title is a title, so it takes .ph-large / .ph-bar-title in the display face like every other page title. In rows, figures and stats it stays mono — that is where it lines up in a column.
11
Measure; do not eyeball. Before claiming a spacing, border or alignment fix, render it headless and read back the actual geometry or pixel values. Several "consistent" edges in this system were measurably not.
12
Check both themes and the fold. Every change gets looked at in light and dark, and at 393 × 852 — content that runs past the fold must clip cleanly, never bisect a button.
13
A box that clips must round its corners uniformly. overflow:hidden plus a mixed border-radius (34px 34px 10px 10px) makes Chromium stop sampling that box's own content for a descendant's backdrop-filter — .ph-material then paints as a flat opaque block instead of blurring the content passing under it, and nothing about the geometry looks wrong while you measure it. This page's minis lost their blur to exactly that. A uniform radius (the device's own 55px, or the minis' 34px) renders correctly. Verified in Chromium only — WKWebView is untested, so any rounded container wrapping the real header gets checked on device.
14
Change the design doc first. Edit foundations/ and these screens, get it approved, then implement in packages/portifo-web. The docs are the source of truth, not a record of what shipped.
15
A chart's baseline never rides on flex:1. A flex item's automatic minimum size lets flex:0 0 116px grow past its basis, so the movers rows whose figure read −$4,004.00 · −3.55% took 129.5px and the rest 116px — which pushed the plot narrower on those rows and put the zero line at 151.8px on two rows and 158.4px on four. Worse than the visible 6.7px kink: each bar is a percentage of its own plot, so the same dollar move meant 82.8px on one row and 89.4px on another and the bars stopped being comparable. Give the plot a fixed share (flex:0 0 42%), let the label column absorb the variation, and put min-width:0 on every sibling. Measure the baseline x on every row, not on the first.
